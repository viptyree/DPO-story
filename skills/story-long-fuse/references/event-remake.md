# Phase 3：事件重做协议

把功能表里每个功能点重做成"功能等价、事件原创"的情节点，填进细纲 `〖事件骨架〗`。

## 重做三判据（每个情节点必须同时满足）

1. **功能等价**：情节点完成功能表标注的读者功能（立威/拉仇恨/爽点兑现/…），强度与位置对齐骨架书节奏。
2. **单源不 1:1**：具体事件（谁、在哪、用什么手段、什么因果）与**任何单本**源书的对应做法不完全相同。允许共享"机制"（如"借宝物反杀"），不允许共享"做法"（如"也是用鼎火在丹房烧了师兄的丹药"）。
3. **因果链不同**：该情节点的前因后果至少一处与原书不同（换了触发条件、换了代价、换了旁观者反应，任一即可）。

## 跨源拼接规则

- 同一章内情节点机制来源必须跨 ≥2 本源书（功能表已按此排布，重做时不得把某点偷偷改回单源做法）。
- 高价值功能点（立威/爽点兑现/回收伏笔）优先用设定源书机制 + 骨架书节奏位置组合——"A 书的人设驱动事件，发生在 B 书的节奏节拍上"是融合感最强的写法。
- 功能表标了 `⚠高重合` 的点：重做幅度加大，因果链必须换两处以上，并在借鉴锚点里注明"高重合点已重做"。

## 逐章生成步骤

对每章 N（1..范围上限）：

1. 读 `融合/事件功能表.md` 该章功能序列与来源标注。
2. 读 `融合/映射表.md`：名词替换、口吻、文风指令、金手指规则。
3. 逐点重做事件（按三判据），产出 `〖事件骨架〗`（可执行、可观察的动作与因果，新书名词）。
4. 按 `references/fuse-outline-contract.md` 模板生成 `大纲/细纲_第NNN章.md`：
   - `〖人物状态〗`：新书名词，本章出场人物的境界/位置/目的/状态。
   - `〖前情〗`：新书名词，开场前局势与必须承接的事实。
   - `〖事件骨架〗`：重做后的情节点，逐点一行；点数 = 功能表该章点数。
   - `〖写作要求〗`：叙事风格（映射表区块5：作者文风指纹优先 + 源书写法补充）、禁止提前释放、结尾（对齐功能表章尾钩子类型）。
   - `## 章节控制`：所属卷、剧情单元=`FU-{N}`、字数目标（映射表统一值）、字数口径=`visible_chars_v1`、视角、章节目标、目标情绪、章尾停笔点。
   - `## 长篇追踪约束`：必须沿用的事实、允许的状态变化、禁止变动的设定、下一章承接的事实。
   - `## 借鉴锚点`（额外工程段，放最后）：见 contract 模板。
5. 双重校验（见下）。
6. 每 5 章一批交付作者抽核。

## 第 1 章特殊处理

- 签约关键章：`〖事件骨架〗` 每个情节点写足可执行细节，不留"制造悬念"类空话。
- 爆点位置对齐功能表（骨架书节奏决定在第几个情节点放反转/爽点），但爆点事件本身必须过三判据。
- `章尾停笔点` 对齐功能表的钩子类型，钩子内容原创。
- 第 1 章的借鉴锚点额外写一行"本章最像哪本源书的哪个位置、靠什么拉开"（作者抽核的主依据）。

## 双重校验

每章落盘后立即跑：

```
node "C:\Users\Tyree\.claude\skills\story-long-write\scripts\check-outline-contract.js" --json --project "{书目录}" --chapter {N}
node "{本skill根}/scripts/check-fuse-outline.js" --project "{书目录}" --chapter {N}
```

- 第一道：DPO 四段式格式（复用 story-long-write 校验器，额外 `##` 段被忽略）。
- 第二道：融合字段（借鉴锚点段字段齐全、功能表引用存在且点数一致、单源贡献占比 ≤50%、禁用原书名词未泄漏进四段式、`⚠高重合` 点有重做标注）。
- 两道都过才算本章完成；任一失败只修指出的字段，不整章重写。

## 批次与抽核

- 默认每 5 章一批：先出第 1/3/5 章供作者抽核，确认后再批量出该批其余章。
- 抽核标准与 go 不同：**作者凭记忆判断"读起来像不像任何一本源书"**，不需要对照原文。像 = 该章事件层重做不够，回步骤 3 重做该章。
- 抽核通过 → 下一批；不通过 → 修该章，再交付。
