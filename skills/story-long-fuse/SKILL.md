# story-long-fuse｜多源融合开书器

## 定位（与 story-long-go 的分工）

| | story-long-go | story-long-fuse（本 skill） |
| --- | --- | --- |
| 策略 | 情节点 1:1 换皮，功能位锁死 | 功能保留、事件重做，跨源拼接 |
| 源书 | 1 本 | 2-3 本（强制 ≥2） |
| 相似度 | 低文字重复、高情节相似 | 低情节相似（无单一原型） |
| 适用 | 签约冲刺、快速上架测试 | 防查重 + 防举报的正式开书 |
| 细纲格式 | DPO 四段式 + `## 换皮对照` | DPO 四段式 + `## 借鉴锚点` |

两者共用 `story-long-write` 的 `dpo-outline-contract.md` 格式和 `check-outline-contract.js` 校验器；额外工程段（换皮对照/借鉴锚点）不进写手 Prompt，正文管线零改动。

## 职责边界（只读拆文库，不拆书，不写正文）

| 本 skill 做 | 本 skill 不做 |
| --- | --- |
| 体检 2-3 个拆文库，判定源书分工 | 拆书（先跑 `/story-long-analyze`） |
| 建情节点级跨书事件功能表，标高重合风险 | 出卷纲、多卷伏笔（前 N 章签约测试用不到） |
| 生成分层映射表（名词/金手指/功能位/口吻/文风指纹），作者确认后锁定 | 写正文、调 DPO 管线、去 AI 味（交给 `/story-long-write`） |
| 事件层重做 + 逐章生成 DPO 四段式细纲（带借鉴锚点） | 改动拆文库原文件（只读） |
| 双重校验（DPO 格式 + 融合字段） | 单源降级（缺第二本就停，建议补拆） |
| 登记多源对标关系、产出融合对照报告、交接 | |

输入：2-3 个拆文库路径（运行时传入）。
输出：本书目录 `融合/源书分工.md`、`融合/事件功能表.md`、`融合/映射表.md`、`大纲/细纲_第NNN章.md`、`融合/fuse-report.md`，并写入 `设定/题材定位.md` 的多源对标登记。

## 路由表

| 阶段 | 权威流程文件 | 停止条件 |
| --- | --- | --- |
| Phase 0 选源、体检与分工 | `references/source-map.md` | 报告缺失/确认分工后停 |
| Phase 1 跨书事件功能表 | `references/function-table.md` | 功能表锁定后停 |
| Phase 2 分层映射表 | `references/layer-mapping.md` | 作者确认并锁定后停 |
| Phase 3 事件重做 + 出细纲 | `references/event-remake.md` + `references/fuse-outline-contract.md` | 每批细纲校验通过、作者抽核后停 |
| Phase 4 交付与交接 | 本文件「交付」节 | 交接命令给出后停，不启动正文 |

裸调用（无参数）时：列出已知拆文库根下的候选书目录，询问哪 2-3 本、各供什么层，然后从 Phase 0 开始。

## Phase 0：选源、体检与分工

按 `references/source-map.md` 执行：

- **强制 ≥2 本**，缺第二本就停，报告 `missing_source`，建议先跑 `/story-long-analyze` 补拆，不做单源降级。
- 每本判定分工层：至少一本供**骨架**（节奏/爽点间隔/钩子类型，取自 `剧情/节奏.md`），至少一本供**设定**（金手指机制/人设，取自 `设定/世界观/金手指.md` + `角色/`）。第三本可选，供场景/桥段/口吻。
- 各书必备文件清单见 source-map.md；逐本体检，缺必备项列出影响。
- 确认范围：默认前 15 章（新书章号连续，不要求与任何一本原书章号对齐）。
- 产出 `融合/源书分工.md`：每本供什么、不供什么、范围章数。

## Phase 1：跨书事件功能表（核心）

按 `references/function-table.md` 执行：

- 从各源书 `章节/第N章_摘要.md` 的 P 情节点提取，**逐情节点**标注：功能（拉仇恨/立威/回收伏笔/引入角色/爽点兑现…）、来源书、原书具体做法一句话、可替换度。
- 跨书合并成一张功能表，标出**高重合风险**：连续 3 章以上功能+事件双重同源（同一本源书贡献了几乎全部情节点）的段落。
- 产出 `融合/事件功能表.md`：按新书章号排列的功能蓝图（每章 = 情节点序列，每点注明功能+来源书+重做要求）。
- 向作者展示功能表（可分章展示），**确认后锁定**。锁定后 Phase 3 只按表做事件重做，不擅自增删功能点。

## Phase 2：分层映射表

按 `references/layer-mapping.md` 生成 `融合/映射表.md`，六个区块：

1. **名词映射**：主源书人名/地名/势力/物品 → 新书（含主角、核心配角、反派、组织）。
2. **金手指映射（功能位等价）**：机制从**设定源书**借；获取/升级/代价三类规则一一对应（规则同 story-long-go 的 skin-mapping，缺一则功能位不等价）。
3. **功能位保留（分源标注）**：逐条引用各源书 `剧情/情绪模块.md` 的 EM 卡，标注"机制来自哪本"；可替换项落到新书名词。
4. **口吻融合**：各源书可识别口吻（从 `文风.md` 提取）→ 融合成新书主角统一口吻，给 2-3 句原句→新句示例。
5. **文风指纹**：从作者记忆（`/story` 作者记忆协议）读作者个性化规则（口头禅/句式/比喻/字数浮动）；读不到则向作者要 2-3 段旧作满意段落现场提炼。写入每章 `〖写作要求〗`，这是防 AI 查重的关键层。
6. **单源上限规则**：任何一本源书对全书的机制贡献 ≤50%（按 EM 卡数计），超限则从其他源书补功能位——结构性保证"没有单一原型"。

生成后向作者展示全文，**确认后锁定**；后续冲突回这里补表，不许在细纲里悄悄改名词。

## Phase 3：事件重做 + 出细纲

按 `references/event-remake.md` 执行，模板见 `references/fuse-outline-contract.md`。

- **与 go 的铁律差异**：
  - 保留：爽点/钩子**位置**对齐功能表（节奏层不动）。
  - 改变：`〖事件骨架〗` 不再 1:1 复刻任何单本源书情节点；每个情节点按功能表重做（换角色/场景/因果链），且同一章内情节点**必须跨 ≥2 本源书机制**拼接（功能表已按此设计）。
  - 事件重做的三个判据：功能等价、单源不 1:1、因果链不同（详见 event-remake.md）。
- 四段式全部用新书名词；`## 借鉴锚点` 段（替代 go 的换皮对照）放最后，含：功能表引用、逐点"来源书原做法→新书新做法"对照、爽点位置对齐记录、高重合风险清单、禁用原书名词（各源书合并）。
- 每章落盘后立即双重校验：
  `node "C:\Users\Tyree\.claude\skills\story-long-write\scripts\check-outline-contract.js" --json --project "{书目录}" --chapter {N}`
  `node "{本skill根}/scripts/check-fuse-outline.js" --project "{书目录}" --chapter {N}`
  （第二道检查：借鉴锚点段字段齐全、功能表引用存在、事件骨架点数=功能表该章点数、单源贡献占比 ≤50%、禁用名词未泄漏进四段式）
- 批次：每 5 章一批，先出 1/3/5 章供作者抽核，抽核重点="读起来像不像任何一本源书"（作者凭记忆判断，不需要对照原文）。

## Phase 4：交付与交接

1. 写 `融合/fuse-report.md`：逐章表（功能序列 / 各点来源书 / 事件重做说明 / 爽点位置是否对齐 / 高重合风险是否消除）。
2. 写 `设定/题材定位.md` 的多源对标登记：各源书=书名+路径+分工层，范围章数，映射表与细纲位置。
3. 给出交接命令：`/story-long-write 开始写第一章`，提醒新书目录需已初始化（`.active-book` 指向本书；首章前走 tracking_init）。
4. **本 skill 到此停**，不启动正文写作。

## 与现有 skill 的接口约定

- 拆文库输入：`/story-long-analyze` 产物（`章节/第N章_摘要.md` 含 P 情节点、`剧情/节奏.md`、`剧情/情绪模块.md`、`文风.md`、`设定/世界观/金手指.md`、`角色/<主角>.md` 为必备）。
- 细纲格式：`references/fuse-outline-contract.md` 与 `story-long-write` 的 `dpo-outline-contract.md` 四段式逐段一致；`## 借鉴锚点` 为唯一新增段，写手编译器不读取。
- 校验器：主校验复用 `story-long-write/scripts/check-outline-contract.js`；融合校验用本 skill `scripts/check-fuse-outline.js`。
- 字数口径：`visible_chars_v1`；默认单章 2500，映射表里定一次，全书统一。
- 剧情单元编号：本书无卷纲时用 `FU-<新书章号>`（如第 6 章=`FU-06`），仅做追溯标记。
- 文风指纹来源：`/story` 作者记忆协议（作者记忆 record）；缺失时 Phase 2 现场向作者采集。
