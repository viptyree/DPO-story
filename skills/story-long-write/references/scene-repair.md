# 本地模型局部修订

适用于主体已完成、只有少量事实或动作错误的场景。主控先读完整原稿和场景计划；模型、截断、情节点缺失或大范围矛盾不能用局部修订绕过。原稿和请求保留，正式正文仍不由主控代写。

在报告 review 指定位置写 JSON：schema_version:1、status:"repair"、原报告 request_sha256、draft_sha256，以及 repairs 列表。每项只含 before（唯一出现的原文）和 instruction（期望事实与动作）；禁止 after 或主控提供替换正文。

一轮1至3段，每段1至500字符、不重叠，总范围最多原稿一半（短稿最低150、最高750字符）。同一场最多两轮，每轮都由主控明确要求；生成后必须重新通读，不自动认可，不自动连续重试。

再次调用写手的 --generate-prepared。脚本以同一本地DPO生成缺口文字，按原文位置替换并重新检查篇幅与重复；产物追加 _repaired，下一轮再追加一次。审阅指向新的文件和指纹。要求改变时不能覆盖已有修订稿，应保留证据并修正计划开始新一轮。

instruction 用正面事实描述谁持有物件、谁在何处、完成何种核验、前后动作怎样连接。引用原段须包含完整句段及对话引号边界，检查其前后是否仍引用被移除物件；不要只改中间一句。避免“逻辑不对”等空话。修订请求只给本场背景、正面事实及缺口左右各100字符，不重复输入错误原句和整篇坏稿；记录保留原句供审计。

例如尸体被错误写成送回家，要求应说明遗体留在收尸处、妻子站在旁边、陆平川尚在核验，并说明这一处动作如何衔接；不要代写想要的小说句子。

修订仍有核心问题、超过两轮或范围过大时停止承接，报告实际错误；修正场景计划后重新生成。标记 pass 必须满足 scene-handoff.md 的原句证据要求。局部修订通过不等于整章通过，拼接后照常核对字数、原版检查与全部连续性。
