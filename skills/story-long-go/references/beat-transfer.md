# Phase 2 节拍迁移协议（方案A：情节点级）

把原书第 N 章的 P1..Pn 情节点，按原顺序、换名词，迁移成新书第 N 章细纲的 `〖事件骨架〗`。

## 迁移铁律

1. **顺序锁死**：原书 P1→P2→…→Pn 的顺序 = 新书 `〖事件骨架〗` 1→2→…→n 的顺序。不增删、不调换。
2. **名词替换**：每个情节点里的人名/地名/物品/组织，按 `换皮/映射表.md` 替换成新书名词。映射表未覆盖的名词 → 回 Phase 1 补表，不新造。
3. **功能位保留**：情节点的「类型/基调」（如「章中反转」「打脸」「获资源」）不变，只换具体事件外壳。
4. **爽点/钩子位置对齐**：原书该章的爽点在第几个情节点，新书同样位置；原书章尾钩子类型，新书 `章尾停笔点` 对齐。
5. **情节点数逐章记录**：原书每章 P 点数不同（如 ch1=5，ch14=10），`换皮对照` 段记录该章实际点数与逐点摘要。

## 逐章生成步骤

对每章 N（1..范围上限）：

1. 读原书 `章节/第N章_摘要.md`，取 P1..Pn。
2. 读 `剧情/节奏.md` 该章对应 EV 条目，确认爽点/钩子位置。
3. 读 `剧情/情绪模块.md`，确认该章生效的 EM 模块（功能位约束）。
4. 读 `换皮/映射表.md`，准备名词替换。
5. 按 `references/go-outline-contract.md` 模板生成 `大纲/细纲_第NNN章.md`：
   - `〖人物状态〗`：用新书名词，写本章出场人物的境界/位置/目的/状态。
   - `〖前情〗`：用新书名词，写本章开场前的局势与必须承接的事实。
   - `〖事件骨架〗`：P1..Pn 逐点一行，可执行可观察，只换名词。
   - `〖写作要求〗`：叙事风格（映射表第5区块）、禁止提前释放、结尾（对齐原书钩子）。
   - `## 章节控制`：所属卷、剧情单元=`GO-N`、字数目标（映射表统一值）、字数口径=`visible_chars_v1`、视角、章节目标、目标情绪、章尾停笔点。
   - `## 长篇追踪约束`：必须沿用的事实、允许的状态变化、禁止变动的设定、下一章承接的事实。
   - `## 换皮对照`（额外工程段，放最后）：对标章节=N、原书情节点数、逐点原书摘要→新书摘要、功能位/EM引用、禁用原书名词列表。
6. 双重校验（见下）。
7. 每5章一批交付作者抽核。

## 第1章特殊处理

- 爆点位置照抄原书第1章（如原书 P5=章中反转，新书同样在 P5 放反转）。
- `章尾停笔点` 对齐原书第1章的钩子类型（悬念/危机/新信息）。
- 第1章是签约关键章，`〖事件骨架〗` 每个情节点写足可执行细节，不留「制造悬念」类空话。

## 双重校验

每章落盘后立即跑：

```
node "C:\Users\Tyree\.claude\skills\story-long-write\scripts\check-outline-contract.js" --json --project "{书目录}" --chapter {N}
node "{本skill根}/scripts/check-go-outline.js" --project "{书目录}" --chapter {N}
```

- 第一道：DPO 四段式格式（复用 story-long-write 校验器）。
- 第二道：换皮字段（对标章节存在、情节点数与原书一致、禁用原书名词未泄漏进四段式）。
- 两道都过才算本章完成；任一失败只修指出的字段，不整章重写。

## 批次与抽核

- 默认每5章一批：先出第1/3/5章供作者抽核，确认后再批量出该批其余章。
- 作者抽核关注点：爽点位置、钩子类型、名词是否全换、情节点顺序是否对齐。
- 抽核通过 → 下一批；不通过 → 修该章，再交付。
