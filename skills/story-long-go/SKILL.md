# story-long-go｜换皮+抄结构启动器

## 职责边界（只读拆文库，不拆书，不写正文）

| 本 skill 做 | 本 skill 不做 |
| --- | --- |
| 体检拆文库目录，报告缺失文件 | 拆书（由其他模型完成，产物已在拆文库里） |
| 生成换皮映射表（名词/金手指/功能位/文风），作者确认后锁定 | 出卷纲、八节点、多卷伏笔（前15章签约测试用不到） |
| 按情节点级逐章生成 DPO 四段式细纲（格式与 `dpo-outline-contract.md` 逐段一致） | 写正文、调 DPO 管线、去AI味（交给 `/story-long-write`） |
| 运行细纲校验器（复用 story-long-write 的 check-outline-contract.js） | 改动拆文库原文件（只读） |
| 登记对标关系、产出换皮对照总表、交接 story-long-write |  |

输入：拆文库路径（运行时传入，默认 `D:\劳动仲裁\novel\yaomo\拆文库\<对标书名>\`）。
输出：本书目录 `换皮/映射表.md`、`大纲/细纲_第NNN章.md`（N=1..15）、`换皮/go-report.md`，并写入 `设定/题材定位.md` 的对标登记。

## 路由表

| 阶段 | 权威流程文件 | 停止条件 |
| --- | --- | --- |
| Phase 0 选源与体检 | `references/source-map.md` | 报告缺失文件或确认范围后停 |
| Phase 1 换皮映射表 | `references/skin-mapping.md` | 作者确认并锁定映射表后停 |
| Phase 2 节拍迁移出细纲 | `references/beat-transfer.md` + `references/go-outline-contract.md` | 每批细纲校验通过、作者抽核后停 |
| Phase 3 交付与交接 | 本文件「交付」节 | 交接命令给出后停，不启动正文 |

裸调用（无参数）时：列出已知拆文库下的对标书目录供选择，询问范围（默认前15章），然后从 Phase 0 开始。

## Phase 0 选源与体检

按 `references/source-map.md` 的必备清单逐项检查拆文库：

- 必备：`剧情/节奏.md`、`剧情/情绪模块.md`、`章节/第1..15章_摘要.md`（每章含 P 情节点）、`文风.md`、`设定/世界观/金手指.md`、`角色/<主角>.md`。
- 可选：`章节/第N章_深度拆解.md`、`设定/世界观/力量体系.md`、`设定/世界观/背景设定.md`、`角色/角色关系.md`。
- 缺必备项：输出 `missing_source` 报告（列出缺什么、影响哪个阶段），停等作者决定（补拆 or 降级）。
- 确认范围：默认前15章；作者指定其他范围时按指定执行，细纲章号与原书章号一一对应。

## Phase 1 换皮映射表

按 `references/skin-mapping.md` 生成 `换皮/映射表.md`，必须包含五个区块：

1. **名词映射**：原书人名/地名/势力/物品 → 新书对应名（含主角、核心配角、反派、组织）。
2. **金手指映射**：原书金手指类型/规则/代价 → 新书金手指（功能位等价：获取方式、升级方式、使用代价三类都要对应）。
3. **功能位保留**：原书每个 EM 模块的「可替换项」逐条落到新书（引用 `剧情/情绪模块.md` 的 EM 卡）。
4. **点睛句保留**：原书标志性句式/吐槽口吻 → 新书主角的等价口吻（参考 `文风.md` 的「不可模仿」节，不照搬可识别素材）。
5. **文风指令**：从 `文风.md` 提炼 3-5 条可写入细纲 `〖写作要求〗` 的叙事风格句。

生成后向作者展示全文，**作者确认后才锁定**（映射表落盘后不再自动改动；后续阶段发现冲突要回这里改，不许在细纲里悄悄改名词）。

## Phase 2 节拍迁移出细纲（方案A：情节点级）

按 `references/beat-transfer.md` 执行，模板见 `references/go-outline-contract.md`。

- **功能位锁死**：第 N 章细纲的 `〖事件骨架〗` = 原书第 N 章 P1..Pn 情节点的顺序，每个情节点一行，只换名词与场景，不增删情节点、不调换顺序。
- **格式零改动**：四段式 `〖人物状态〗〖前情〗〖事件骨架〗〖写作要求〗` 与 `## 章节控制`、`## 长篇追踪约束` 的段名、字段名、字段顺序与 `dpo-outline-contract.md` 完全一致。新增的 `## 换皮对照` 是**额外工程段**，放在 `长篇追踪约束` 之后；`build_dpo_prompt.py` 只取固定段名，该段不会进写手 Prompt。
- `〖人物状态〗`/`〖前情〗`/`〖写作要求〗` 全部使用**新书名词**（按映射表替换），不出现原书人名。
- 第1章特殊处理：爆点位置照抄原书第1章（原书 P5 落刀=章中反转，新书同样位置放反转）；`章尾停笔点` 对齐原书第1章的钩子类型。
- 每章落盘 `大纲/细纲_第NNN章.md` 后立即校验：
  `node "C:\Users\Tyree\.claude\skills\story-long-write\scripts\check-outline-contract.js" --json --project "{书目录}" --chapter {N}`
  再跑本 skill 增量校验：`node {本skill根}/scripts/check-go-outline.js --project "{书目录}" --chapter {N}`（对标章节存在、情节点数与原书一致、禁用原书名词列表非空且未泄漏进四段式）。
- 批次：每5章一批交付作者抽核（默认先出1/3/5章供确认），确认后再批量出剩余章。

## Phase 3 交付与交接

1. 写 `换皮/go-report.md`：15章对照表（原书章节 → 原书关键事件一行摘要 → 新书情节点一行摘要 → 爽点/钩子位置是否对齐）。
2. 写 `设定/题材定位.md` 的对标登记段：主对标书=拆文库书名+路径，对标范围=前15章，换皮映射表位置，细纲位置。
3. 给出交接命令：`/story-long-write 开始写第一章`，并提醒：新书目录需已初始化（`.active-book` 指向本书；首章写作前 story-long-write 会走 tracking_init）。
4. **本 skill 到此停**，不启动正文写作。

## 与 story-long-write 的接口约定

- 细纲格式：`references/go-outline-contract.md` 与 `C:\Users\Tyree\.claude\skills\story-long-write\references\dpo-outline-contract.md` 的四段式逐段一致；`## 换皮对照` 为唯一新增段，写手编译器不读取。
- 校验器：主校验复用 `C:\Users\Tyree\.claude\skills\story-long-write\scripts\check-outline-contract.js`；增量校验用本 skill 的 `scripts/check-go-outline.js`。
- 字数口径：`visible_chars_v1`；默认单章目标 2500，可按原书章均字数微调（在映射表里定一次，15章统一用）。
- 剧情单元编号：本书无卷纲，`剧情单元` 字段用 `GO-<原书章节号>`（如第6章=`GO-06`），仅做追溯标记。
